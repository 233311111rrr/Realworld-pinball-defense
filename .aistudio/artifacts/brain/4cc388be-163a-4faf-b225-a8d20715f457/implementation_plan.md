# 星際彈球防衛戰 — 怪物血量成長曲線、寶箱機率調降與狀態更新修復計畫

本計畫針對戰鬥節奏進行數值平衡調整，加快每排怪物的血量成長幅度、降低寶箱出現頻率，並同步修復擊破怪物時跨元件更新最高分所觸發的 React 渲染錯誤，確保 **Web 即時預覽版** 與 **Android 原生專案** 完全一致。

### User Review & Critical Decisions

> [!IMPORTANT]
> 以下為您於問答階段確認的數值設定與系統修復項目，確認後將立即套用至遊戲引擎與 Android 原始碼：

- **確認決策 1（怪物血量成長幅度）**：每排怪物基礎血量成長率由原本的 `+8%` 提升至 **`+15%`**（`MONSTER_HP_ROW_GROWTH_RATE = 0.15`），讓中後期波次血量爬升更有挑戰感，貼合街機高壓防守體驗。
- **確認決策 2（寶箱生成頻率調降）**：單格怪物生成寶箱的機率由原本的 `6%` 調降為 **`3%`**（`CHEST_SPAWN_CHANCE = 0.03`），以每排 14 隻計算，平均約 **2 至 3 排** 出現 1 個金色寶箱，避免寶箱過於密集。
- **系統錯誤修復（React 跨元件狀態同步）**：將最高分同步回調移出 `setCurrentScore` 的狀態計算函式，改由獨立 `useEffect` 監聽分數變化，徹底消除 `Cannot update a component (App) while rendering a different component (GameCanvas)` 錯誤。

### 1. Overview & Core Concept

- **功能目標**：強化街機闖關的難度遞進曲線，讓玩家更能感受到火力升級與電漿雷射、導引飛彈技能卡的價值，同時維持技能寶箱的稀有度與驚喜感。
- **適用對象**：體驗即時戰鬥預覽或編譯 Android APK 進行高幀率闖關的玩家。
- **核心價值**：平衡每波次血量成長與技能獲取節奏，並確保擊破怪物、寶箱與首領時畫面流暢無報錯。

---

### 2. User Experience & Visual Design

- **核心遊戲體驗流程**：
  1. 開局第 1 波怪物以 `100` 基礎血量自右上角入口依序往左進場。
  2. 隨著波次推進，每新增一排怪物，血量按 `1.15^(wave - 1)` 倍率穩定攀升（例如第 10 波約 `352`、第 25 波約 `2,862`、第 40 波突破 `23.3K`），頭頂動態顯示 `K / M` 血量標記。
  3. 金色寶箱以 `3%` 機率混入行軍隊伍中（血量為同排怪物的 `60%`），平均每 2～3 排出現 1 個，擊破後於安全時機彈出三選一技能抽卡視窗。
- **視覺與介面規範**：
  - *美學風格*：2D 街機卡通精靈風格（深紫星空背景、金屬鑲邊頂部計分板與底部凹槽道具欄）。
  - *色彩配置*：60% 深空紫藍戰場底色（`#17132c`）、30% 金屬深灰面板（`#282838`）、10% 琥珀金寶箱與青色電漿特效強調色（`#fbbf24`、`#38bdf8`）。
  - *字體與數值對齊*：頂部金幣、得分、最佳紀錄與怪物頭頂血量統一採用等寬數字對齊（`tabular-nums`），避免高速跳分時文字晃動。

### 3. Key Product Decisions & Trade-Offs

- **決策 1：採用每排 +15% 指數成長曲線 (`0.08 -> 0.15`)**
  - *選擇方案*：將 `MONSTER_HP_ROW_GROWTH_RATE` 設為 `0.15`。
  - *原因*：原本 `+8%` 在前 20 排血量增長過慢，彈球與雷射容易瞬間秒殺整排；提升為 `+15%` 後，前 5 排保持爽快清怪，第 10 排起明顯感受到血量厚度，促使玩家善用冰凍、炸彈與雙倍傷害道具。
- **決策 2：寶箱生成機率減半 (`0.06 -> 0.03`)**
  - *選擇方案*：將 `CHEST_SPAWN_CHANCE` 設為 `0.03`。
  - *原因*：每排 14 隻怪物下，`6%` 機率幾乎每排都有寶箱，導致抽卡彈窗頻繁打斷射擊節奏；調降為 `3%` 後平均每 2～3 排出現 1 個寶箱，兼顧養成樂趣與射擊連貫度。
- **決策 3：分離計分狀態更新與父元件最高分回寫**
  - *選擇方案*：在 `onMonsterDefeated` 中僅執行 `setCurrentScore((prev) => prev + bonus)`，並透過 `useEffect` 在 `currentScore > bestScore` 時呼叫 `onBestScoreChange(currentScore)`。
  - *原因*：React 嚴格禁止在子元件的 `setState` 計算閉包內直接呼叫父元件的 `setState`，分離後可確保 240Hz 物理碰撞結算時完全符合 React 渲染生命週期。

### 4. Technical Architecture & Data Strategy *(Technical Reference)*

- **系統架構與數值流向圖**：

```
┌─────────────────────────────────────────────────────────────────┐
│                   全域數值配置 (GameConfig)                      │
│  • MONSTER_HP_ROW_GROWTH_RATE : 0.08 ──► 0.15 (每排血量 +15%)   │
│  • CHEST_SPAWN_CHANCE         : 0.06 ──► 0.03 (寶箱機率 3%)     │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                蛇形波次生成器 (SnakeGrid / WaveSpawner)          │
│  • baseHp = 100 × (1.15)^(waveCount - 1)                        │
│  • isChest = !isBoss && rand() < 0.03 (HP = baseHp × 0.6)       │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                擊破結算與狀態同步 (Score & State Sync)           │
│  • 擊破怪物/寶箱/Boss ──► setCurrentScore(prev => prev + score)  │
│  • useEffect([currentScore]) ──► 若超越最佳紀錄則同步至父層 App   │
└─────────────────────────────────────────────────────────────────┘
```

- **互動與狀態映射**：
  - **波次推進**：當上一排尾端進入右上角起點後，自動依據新成長率計算下一排怪物血量並判定是否混入 `3%` 機率寶箱。
  - **分數與紀錄持久化**：擊破敵人即時累加當局得分，並由獨立副作用安全更新頂部 HUD「最佳」分數與 `localStorage` / `SharedPreferences` 紀錄。
